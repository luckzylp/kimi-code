## ACP × Zed bug: terminal release wedging the session (fixed, commit `b5aba5858`)

Root cause chain:
1. `bashTool.executeProcess()` `finally` → `proc.dispose()` →
   `AcpTerminalProcess.dispose()` → ACP `terminal/release` — this runs **before**
   the engine publishes `tool.result`.
2. Zed deletes the terminal on release.
3. `AcpSession.onToolResult` then emitted `tool_call_update` with
   `content: [{type:'terminal', terminalId}]` for the just-released terminal.
4. Zed rejects the update: `Failed to handle session update ... Terminal with id
   ... not found` (seen in `%LOCALAPPDATA%\Zed\logs\Zed.log`). The thread's
   update pipeline stops → no UI updates, `session/prompt` never settles (send
   button grey) — while the agent keeps running and history keeps growing.

Fix (in `packages/acp-server`):
- `IAcpConnection.deferTerminalRelease/releaseTerminal/releaseSessionTerminals`:
  park a release, 5s fallback timer, fire-and-forget.
- `AcpTerminalProcess.dispose()` parks instead of awaiting — removes both the
  ordering bug and the hang risk of an unanswered reverse-RPC on the tool path.
- Session claims the release at `tool.result` after pushing the final update;
  that update now carries a bounded (16 KiB tail) text preview instead of a
  terminal embed, and omits `rawOutput` so a ~10 MB capture cannot become one
  giant JSON-RPC frame.
- `AcpSession.dispose()` releases leftover parked terminals.

Generated `patches/0004-acp-terminal-release-ordering.patch` (kept in /tmp during
the session) and verified the chain 0001→0004 applies to a pristine upstream
tarball with `patch -p1` and reproduces main's `packages/acp-server` tree.
Shipping path: add 0004 to `opt/acp-server-patches`, run the
"Patch Native Release" workflow (globs `patches/[0-9]*.patch`), then
`scripts/update-zed-cache.ps1`.
